## 1. 文档概述

### 1.1 背景
随着大语言模型（LLM）、端到端语音识别与合成技术的快速发展，机器人已经能以接近自然对话的方式与人类进行交互。用户对"按键式"或"唤醒词+固定指令"的传统交互方式日益不满，期待机器人能够像真人一样听得清、听得懂、答得准、答得快、说得自然。本项目将围绕"全双工、拟人化、多模态"的目标，构建一套通用的机器人语音交互系统。

### 1.2 目标
- 让机器人具备"听—懂—答—说"的完整链路能力，满足 95% 以上日常交互场景的需求。
- 端到端首响应时延 ≤ 800ms，打断延迟 ≤ 300ms。
- 支持多轮对话、上下文记忆、主动发起对话。
- 支持多方言、多语种、多音色，并具备情感表达能力。
- 提供可扩展的技能接入框架，便于业务方快速落地。

### 1.3 术语表
| 缩写 | 全称 | 说明 |
| --- | --- | --- |
| ASR | Automatic Speech Recognition | 语音识别，将音频转成文字 |
| TTS | Text To Speech | 语音合成，将文字转成音频 |
| NLU | Natural Language Understanding | 自然语言理解 |
| DM | Dialog Management | 对话管理 |
| NLG | Natural Language Generation | 自然语言生成 |
| VAD | Voice Activity Detection | 语音端点检测 |
| KWS | Keyword Spotting | 唤醒词检测 |
| AEC | Acoustic Echo Cancellation | 回声消除 |
| BF | Beamforming | 波束形成 |
| LLM | Large Language Model | 大语言模型 |
| TTFB | Time To First Byte | 首字（首包）响应时间 |
| Barge-in | — | 用户在机器人说话中打断 |

## 2. 用户与场景

### 2.1 目标用户
- **C 端用户**：家庭成员（老人、儿童、成年人），追求自然陪伴与信息问答。
- **B 端用户**：酒店、医院、银行、展馆等运营方，追求导览、导办、讲解。
- **开发者**：SDK 接入方、技能开发者。

### 2.2 典型场景
1. **唤醒—问答**：用户通过唤醒词或免唤醒方式呼叫机器人，询问天气、时间、百科知识。
2. **连续多轮对话**：机器人记住上下文，可持续进行 5 轮以上对话。
3. **任务执行**：用户通过语音下发指令（播放音乐、设置闹钟、控制家电、导航到某展位）。
4. **被打断场景**：机器人正在播报内容时，用户插话，机器人能即时停止并响应。
5. **噪声场景**：商场、展馆等嘈杂环境下仍能准确识别。
6. **多人场景**：区分说话人并聚焦当前发言者。
7. **主动交互**：识别到人脸或靠近，机器人主动问候。
8. **离线降级**：网络断开时，基础指令（音量、返回、停止）仍可响应。

### 2.3 用户画像（示例）
| 画像 | 特征 | 典型需求 |
| --- | --- | --- |
| 张奶奶，68 岁 | 独居，方言口音 | 聊天、听戏、提醒吃药 |
| 小明，6 岁 | 好奇心强 | 百科问答、讲故事、学英语 |
| 李经理，35 岁 | 酒店前台 | 指引客人到房间、多语言接待 |

## 3. 产品定位与范围

### 3.1 产品定位
面向机器人本体的**通用语音交互中台**，向下对接硬件（麦克风阵列、扬声器、传感器），向上对接业务技能（智能家居、导览、问答、情感陪伴）。

### 3.2 本期范围（In Scope）
- 全双工语音交互引擎（ASR + NLU + DM + NLG + TTS）
- 唤醒 / 免唤醒 / 打断
- 多轮对话与上下文管理
- LLM 对接与安全护栏
- 多方言、多语种、多音色
- 技能插件框架（Skill SDK）
- 管理后台（话术、技能、数据统计）

### 3.3 非本期范围（Out of Scope）
- 机器人运动控制
- 视觉识别（仅保留接口，由视觉团队提供）
- 专用行业知识库（由业务方自行接入）

## 4. 功能需求

### 4.1 功能总览

```
┌──────────────────────────────────────────────────────────┐
│                       业务技能层                          │
│  智能家居 │ 百科问答 │ 导览 │ 闲聊 │ 音乐 │ 提醒 │ ...     │
├──────────────────────────────────────────────────────────┤
│                     对话管理 (DM)                         │
│  意图路由 │ 多轮上下文 │ 状态机 │ 安全护栏 │ 降级策略       │
├──────────────────────────────────────────────────────────┤
│            语音理解 (NLU / LLM)   语音生成 (NLG)          │
├──────────────────────────────────────────────────────────┤
│    ASR    │   VAD   │   声纹   │   TTS   │  情感/韵律     │
├──────────────────────────────────────────────────────────┤
│       前端信号处理：AEC / BF / 降噪 / 去混响 / KWS         │
├──────────────────────────────────────────────────────────┤
│     硬件抽象：麦克风阵列 / 扬声器 / 本地算力 / 网络        │
└──────────────────────────────────────────────────────────┘
```

### 4.2 详细功能

#### F-01 语音唤醒
- 支持自定义唤醒词，默认提供 1 个出厂唤醒词；
- 支持唤醒 + 免唤醒双模式，免唤醒需通过声纹 + 语义双门限；
- 5m 内唤醒率 ≥ 95%，误唤醒 ≤ 0.5 次 / 24h；
- 唤醒后 200ms 内给出视觉 / 声效反馈。

#### F-02 前端信号处理
- 支持 2/4/6 麦克风阵列；
- AEC：外放 TTS 时本机声音不被二次识别；
- 波束形成：自动对准主说话人；
- 降噪 SNR 提升 ≥ 10 dB。

#### F-03 语音识别（ASR）
- 普通话识别字准 ≥ 97%（安静环境）、≥ 92%（典型家居噪声）；
- 流式识别，首包 ≤ 300ms；
- 支持中英混说、数字 / 人名 / 地名热词；
- 至少支持 6 种方言（粤、川、闽、吴、晋、东北）与 4 种外语（英、日、韩、西）。

#### F-04 自然语言理解（NLU）
- 规则 + 语义向量 + LLM 三段式识别；
- 支持意图（Intent）+ 槽位（Slot）结构化输出；
- 支持指代消解、省略补全、话题切换。

#### F-05 对话管理（DM）
- 上下文保持至少 10 轮或 10 分钟，可配置；
- 支持任务型（闹钟、家电）与问答型（百科、闲聊）双路由；
- 支持多技能并发与优先级抢占；
- 打断后保留任务现场，允许用户稍后继续。

#### F-06 大模型（LLM）接入
- 支持私有云 / 公有云 LLM 可切换；
- Prompt 模板化、可热更新；
- 支持工具调用（Function Calling）；
- 内容安全：涉黄、涉政、涉暴关键词过滤 + 语义安全模型双审。

#### F-07 语音合成（TTS）
- 至少 6 种音色（男 / 女 / 童 / 老人 / 明星音色 2 种）；
- 支持情感标签（中性、开心、安慰、抱歉、兴奋）；
- 支持流式合成，TTFB ≤ 300ms；
- MOS ≥ 4.3。

#### F-08 全双工与打断
- 用户可在机器人说话过程中随时插话；
- 打断响应延迟 ≤ 300ms；
- 支持"让我说完"策略，可在高优先级播报（如告警）时暂不响应打断。

#### F-09 声纹与多人
- 声纹注册：3 段 ≥ 5 秒音频完成；
- 识别准确率 ≥ 95%；
- 多人同时发言时，定位并聚焦主说话人。

#### F-10 主动交互
- 结合视觉/距离传感器，1.5m 内识别到人脸 3 秒，主动问候；
- 支持按时间、日程、位置触发主动提醒。

#### F-11 离线降级
- 网络中断时，本地至少保留 50 条核心指令（停止、音量、播放、取消、重复等）；
- 断网恢复后自动同步上下文。

#### F-12 技能 SDK
- 提供 Python / Node / Go 三语言 SDK；
- 技能可声明意图、槽位、话术模板、回调地址；
- 提供本地仿真器与 CI 测试框架。

#### F-13 管理后台
- 话术管理、技能上下线、灰度发布；
- 调用量、唤醒率、识别率、用户满意度仪表盘；
- 对话日志检索（脱敏）、Badcase 标注；
- 权限与审计。

## 5. 非功能需求

| 类别 | 指标 |
| --- | --- |
| 首响应时延 | 端到端 ≤ 800ms（P95） |
| 打断延迟 | ≤ 300ms |
| 并发 | 单机 ≥ 1 路，云端 ≥ 10k QPS |
| 可用性 | 云端 99.9%，本地功能 99.99% |
| 功耗 | 待机 < 3W，交互峰值 < 8W |
| 安全 | 数据传输 TLS1.3，静态加密 AES-256；符合 GDPR / 个保法 |
| 隐私 | 默认不上传原始音频，仅上传特征或文本；用户可一键清除 |
| 可观测 | 全链路 Trace，指标接入 Prometheus / OpenTelemetry |
| 本地化 | UI / 语音支持中、英、日、韩、西 5 种语言 |
| 升级 | OTA 热更新，回滚时间 ≤ 5min |

## 6. 系统架构

### 6.1 总体架构
- **端侧**：VAD / KWS / AEC / 降噪 / 本地兜底 ASR 和 TTS；
- **云侧**：流式 ASR、NLU、DM、LLM、TTS、知识库、技能路由；
- **管理侧**：Portal、数据平台、监控告警。

### 6.2 端云协同策略
| 场景 | 端侧 | 云侧 |
| --- | --- | --- |
| 安静环境 + 普通指令 | 识别 + 合成 | 备份 |
| 复杂问答 | 采集 + VAD | 全链路 |
| 断网 | 全链路兜底 | — |

### 6.3 关键接口（示意）
- `POST /v1/asr/stream`  流式音频上行，文本下行
- `POST /v1/dialog`  文本输入，结构化回复 + TTS 流
- `POST /v1/tts/stream`  文本上行，音频下行
- `POST /v1/skill/invoke`  技能调用
- `GET  /v1/session/{id}`  上下文查询

## 7. 交互设计（要点）

- **视觉反馈**：屏幕/灯带在"倾听""思考""回答"三个状态使用不同颜色与呼吸节奏。
- **语音反馈**：唤醒提示音 ≤ 200ms，可自定义；回答开始前 300ms 内给出确认音效（可配）。
- **可打断提示**：TTS 播报中持续监听，无需用户再次唤醒。
- **失败兜底**：连续 2 次未理解后，机器人主动给出可选意图或询问确认。
- **人格设定**：默认"亲切、礼貌、简洁"人格，B 端可定制品牌人格。

## 8. 数据与模型

### 8.1 数据需求
- 采集渠道：真实用户（已授权）、众包、公开数据集。
- 标注：音素级、字级、意图槽位级；标注一致率 ≥ 95%。
- 数据闭环：线上 Badcase → 人工复核 → 回流训练集 → 模型迭代。

### 8.2 模型指标
| 模型 | 指标 | 目标 |
| --- | --- | --- |
| KWS | 召回 / 误触发 | ≥ 95% / ≤ 0.5 次/天 |
| ASR | CER（安静/嘈杂） | ≤ 3% / ≤ 8% |
| NLU 意图 | F1 | ≥ 92% |
| TTS | MOS | ≥ 4.3 |
| 安全模型 | 有害内容召回 | ≥ 99% |

---

## 9. 安全与合规

- 唤醒前不上传任何音频；
- 提供物理"麦克风静音"开关；
- 未成年人模式：限制内容与时长；
- 所有对话记录 90 天自动清理（可配置）；
- 数据出境合规：就近数据中心、必要时脱敏；
- 供应链：三方模型与数据使用需有授权与审计。

## 11. 验收标准（摘要）

1. 指标达标：第 5 节所有性能与质量指标均达到目标值。
2. 场景通过：第 2.2 节所列 8 个典型场景端到端通过。
3. 压测：云端 10k QPS 持续 1 小时，P95 < 800ms、错误率 < 0.1%。
4. 安全：通过公司内部安全评审、渗透测试与合规审查。
5. 用户验收：外部用户 NPS ≥ 40，Badcase 闭环机制运转正常。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| LLM 回答幻觉 / 不安全 | 用户体验、品牌 | RAG + 安全护栏 + 灰度 + 人审 |
| 噪声场景识别率低 | 核心体验 | 阵列优化 + 噪声数据增强 + 端云协同 |
| 网络抖动 | 时延不稳 | 本地兜底 + 断点续传 + 区域调度 |
| 数据隐私 | 合规风险 | 最小化采集 + 脱敏 + 本地化处理 |
| 方言覆盖不足 | 长尾用户流失 | 数据众包 + 自适应训练 |
